# Инженерные изменения: что есть, чего нет и как идти дальше

Предложение по ТЗ «Engineering Change Visualization». Это этапы A и B: исследование и архитектура. Кода здесь нет, решения ждут проверки лидером.

## Коротко

- Главная боль не в картах отклонений, а в трёх вещах: **забывается, зачем менял; папки ведутся вручную; не видно, какая версия где стоит.**
- Вторая система хранения не нужна. Всё ложится на git: версия — коммит, вариант — ветка со своей рабочей папкой, версия проекта — метка на коммите.
- Слияния (`merge`) в Nonius не будет. Это прежнее решение проекта, и опыт его подтвердил. Деталь переносится между вариантами отдельным действием.
- Окно: **дерево слева, рабочая зона по центру, карта снизу.** Лидер принял кликабельный эскиз как первую рабочую версию, дальше правки по ходу проверки. [Эскиз](https://claude.ai/artifact/2D3tiHNHWdpCFB6om6Tc1c) доступен по ссылке только владельцу.
- Первый шаг не требует новых форматов: вкладки «Файлы» и «Числа» у версии.

## 1. Как работает Владимир

Ответы на вопросы, из них выросла модель.

| Как в жизни | Что это значит для Nonius |
|---|---|
| Деталь 1 → 1.1 → 1.3, правки «махом», без объяснений | Обычная работа — цепочка версий. Описание не должно мешать сохранять |
| Через неделю хочется дописать, зачем менял | Заметка живёт отдельно от версии и дописывается когда угодно |
| Есть важные версии: «в производстве», «стоит в механизме» | Нужны отметки на версиях |
| Папки и копии деталей ведутся вручную, это неудобно | Папки ведёт Nonius, неизменённые детали переходят в новую версию проекта сами |
| Новая деталь рождается из старой | Нужна связь «сделана из» |
| Бывает новая версия, бывает новая деталь, бывает обе живут дальше | Поддерживаем оба случая |
| В варианте А стоит вал v3, в основной появился v4 | Вариант остаётся на v3. Nonius только подсказывает, обновляет человек |
| Иногда меняется одна деталь, иногда несколько по одной причине | Группа изменений по желанию |
| У каждого варианта своя папка, аддин сам сохраняет куда надо | Одно хранилище, несколько рабочих папок |
| При детали: чертежи токарю, резка, PowerMill, технология, заметки | Вкладка «Файлы», текст и числа сравниваются, остальное показывается как файл |

## 3. Что показал опыт с ветками

Опыт на временном проекте, программой от 26 октября. Код версий и служебной папки в `main` по этой части тот же.

| Проверка | Итог | Что делать |
|---|---|---|
| Сохранить версию в двух ветках | Два разных `вал v3` | Считать номер по всем вариантам сразу (`git log --all`) |
| Слить ветки через `git merge` | Один `v3` пропал из истории в программе | Слияния не делаем |
| Деталь есть только в другой ветке | В списке её не видно | Для других вариантов читать список из git, а не из папки |
| Отдельная папка (`git worktree`) | Версия сохраняется, **сравнение падает** | `work_dir` ищет папку `.git`, а там файл. Брать путь через `git rev-parse --git-common-dir` |
| Имя ветки с пробелом | git не принимает | Показываем «под заказчика А», внутри пишем `вариант/под_заказчика_А` |
| Переключение с несохранёнными файлами | git отказывает | Отдельные папки это снимают |

Нужна ещё одна правка до аддина. Nonius называет исходник любой детали `model.sldprt`. Насколько мы знаем, SolidWorks не открывает одновременно два файла с одним именем, а значит, в сборке они будут мешать друг другу. Это надо проверить в SolidWorks. Из-за этого же запрета оба варианта, скорее всего, можно открыть только в двух отдельных запусках программы.

## 4. Где ТЗ расходится с архитектурой

| В ТЗ | Проблема | Замена |
|---|---|---|
| Девять состояний на одной шкале | Смешаны три разных вопроса: деталь могут изменить и уже проверить | Три оси: что с файлами, что с последствиями, что с проверкой |
| ChangeSet как одно целое | Правило проекта: версия меняет только папку своей детали. Общий коммит сломает разбор истории | Отдельные версии с общей строкой `Nonius-Change` |
| ChangeImpact как сущность | Устаревает сразу, это расчёт, а не факт | Считать на лету, не хранить |
| Decision как отдельная сущность | Вторая система заметок | Заметка Markdown в `notes/`, как в Obsidian |
| Review, Task, Requirement сейчас | Человек работает один, это этап 6 | Потом. Задачи — в Forgejo |
| Семь видов связей сразу | Заполнять будет некому | Сначала «сделана из» и «взята из», остальные с заметками и сборками |
| Deviation и Assembly Diff сразу | Нет сцены и сборок | Оставить контракт: модули `Comparator` и `Renderer`, формат сцены с номером |
| «Альтернатива системам контроля версий» | Nonius работает поверх git | Формулировка: инженерный слой поверх git |

Слово «ветка» остаётся внутри. По правилам проекта человек видит «версию» и «вариант», а не `commit`, `merge` и `HEAD`. Прежнее решение «варианты вместо веток» не отменяется: снаружи вариант, внутри ветка git, слияния нет.

Мелочи в документах: в таблице точек расширения `Ui` ещё упомянут веб-интерфейс, а в этапах этап 2 не отмечен готовым.

## 5. Модель данных

### Что нужно сейчас

| Сущность | Простыми словами | Где живёт |
|---|---|---|
| Деталь | Папка в `parts/` или `assemblies/` | как сейчас |
| Версия | Снимок папки детали | коммит, как сейчас |
| Заметка к версии | «Зачем поменяли», дописывается в любой момент, текст и отметка («в производстве») | `notes/версии/<деталь>/v3.md` |
| Вариант | Параллельная линия конструкции со своей папкой | ветка `вариант/<имя>` + `git worktree` |

Заметка не трогает папку детали, поэтому деталь не становится изменённой и новой версии не появляется. Файл новый, в начале `schema: 1`. Существующие схемы не меняются, Obsidian его открывает.

```text
---
schema: 1
item: кронштейн
version: v3
commit: 8c6546a5…
status: в производстве
author: Владимир
source: человек
---
Сместил отверстие под вал, мешал корпус редуктора.
```

Заметки читаются по всем вариантам сразу, поэтому заметка, написанная в варианте А, видна и в основной конструкции.

### Что нужно потом

| Сущность | Простыми словами | Где живёт |
|---|---|---|
| Версия проекта | «Проект v2: вал v3, кронштейн v5» | метка git `nonius/project/2` на коммите |
| Группа изменений | Одна причина на несколько деталей | строка `Nonius-Change` в сообщении коммита |
| Связь «взята из» | Деталь пришла из другого варианта | строка `Nonius-From: <вариант> v4 <коммит>` |
| Связь «сделана из» | Новая деталь родилась из старой | строка `Nonius-Derived-From: вал@v3` в первой версии |
| Состав сборки | Какие детали и какие их версии | новый файл в папке сборки, этап 9 |
| Решение | Проблема, альтернативы, обоснование | заметка `notes/` с полем вида, этап 7 |
| Утверждение | Лидер принял версию | формат на этапе 6 |
| Утверждения ИИ | Кто сказал, откуда, проверено ли | поля `source` и `status` в заметке, этап 5 |

Метки и строки в сообщениях не меняют `project.yaml`, `meta.yaml` и `tree.yaml`, миграция не нужна. Старые программы показывают новые строки как часть описания и не ломаются.

Не храним, а считаем: «потенциально затронуто», «устарело», граф и карту. Хранятся только факты, поэтому они не расходятся.

### Как ветки связаны с остальным

```text
 основная      v1 ── v2 ── v3 ──────── v4
                            \
 вариант А                   v5 ── (вал v3 закреплён)
```

- **Вариант и версия.** Вариант — это линия версий. Начало общее, дальше своё. Номер версии у детали один на все варианты, поэтому `v5` всегда означает одно и то же.
- **Вариант и файлы.** В папке варианта видны его файлы, документы и текстовое сравнение с предыдущей версией, как в основной.
- **Вариант и зависимость.** Вариант закреплён сам собой: у него лежит та версия, которая в его ветке. Новая версия из основной к нему не придёт. Nonius сравнивает и пишет: «здесь вал v3, в основной есть v4».
- **Перенос.** «Взять из другого варианта» одна на два случая: обновить деталь и сделать вариант основным. Файлы детали копируются, номер сохраняется, строка `Nonius-From` записывает, откуда. Git-слияния нет.
- **Вариант и группа.** Группа живёт внутри одного варианта.
- **Закрытие.** Вариант уходит в архив: папку можно убрать, ветка остаётся. Ничего не удаляется.

## 6. Как части встают в программу

| Крейт | Что добавится |
|---|---|
| `nonius-core` | Формат заметки к версии, имя варианта |
| `nonius-store` | Файлы и текст разницы между версиями, версии по всем веткам, варианты, метки |
| `nonius-app` | Те же действия для окна, команд и MCP |
| `nonius-gui` | Лента, вкладки, карта, через `ProjectSource` |
| `nonius-cli` | Команды к тем же действиям, мост в `window.rs` |

Новых точек расширения на первых шагах нет. Окно по-прежнему не знает про git. Карта рисуется средствами egui, отдельная библиотека не нужна.

## 7. Окно

```text
┌──────────────────────────────────────────────────────────────────┐
│ Папка: Основная      [Сохранить версию] [Новый вариант] [Версия] │
├────────────────────────┬─────────────────────────────────────────┤
│ Поиск, фильтры         │ кронштейн · сейчас       не сохранено   │
│ ▾ Основная  папка      │ Было [v4 ▾]  Стало [Сейчас ▾]           │
│   ▾ кронштейн v4  ●    │ [Было] [Изменения] [Стало]  │ Места     │
│     Сейчас, не сохр.   │        3D-вид               │ Зачем     │
│     v4 Бобышки         │                             │ Файлы     │
│     v3 В производство  │ Места: + Фаска на бобышках  │ Текст     │
│   ▸ вал v4             │                             │ Числа     │
│ ▸ Под заказчика А      │                             │ Связи     │
├────────────────────────┴─────────────────────────────────────────┤
│ Карта: [Деталь] [Весь проект]                                    │
│  Под заказчика А            (v5)───(v7)                          │
│  Основная  (v1)(v2)(v3)──9 дн.──(v4)                             │
│  1 окт          5 окт        14 окт       20 окт     27 окт      │
└──────────────────────────────────────────────────────────────────┘
```

Главное правило: щелчок в дереве или на карте открывает выбранное по центру. Функции зон могут повторяться, это решение лидера.

| Зона | Что в ней |
|---|---|
| Дерево | Вариант → деталь → версии, как дерево построения в SolidWorks. Первая строка у изменённой детали — «Сейчас, не сохранено». Поиск и фильтры «Без причины», «С отметкой» |
| Центр, выбран вариант | Описание, папка, состав с пометками «своя», «общая», «есть новее», кнопка «Обновить», версии проекта, что не объяснено |
| Центр, выбрана версия | Поля «Было» и «Стало», в том числе из разных вариантов, режимы 3D, список мест, вкладки «Зачем», «Файлы», «Текст», «Числа», «Связи» |
| Карта | Деталь: версии по вариантам, даты, подписи пауз. Весь проект: какой вариант из каких деталей состоит, пунктир — стоит старая версия |
| Окно сохранения | Одна или несколько деталей, одна причина на всех, поле можно оставить пустым |

На карте зелёный круг означает важную отметку, толстый — есть заметка, рыжая точка — причины нет, треугольник — версия лежит в открытой папке. Метка «папка открыта» показывает, где сейчас рабочие файлы.

Единая запись везде: «причина не указана» вместо пустого места. ИИ может предложить причину, но она останется предложением, пока человек её не подтвердит.

## 8. Порядок работ

Каждый шаг — один PR. Проверка идёт на отдельном тестовом проекте из копий `Test V1` и `Test V2`, настоящие детали не меняются.

| № | Шаг | Что увидишь в окне | Как проверить |
|---|---|---|---|
| 1 | Вкладки «Файлы» и «Числа» | Щёлкнул версию: файлы с пометками, текст по строкам, кнопка «Открыть» | Положи чертёж в `docs/`, сохрани версию, увидь его в списке и открой |
| 2 | Заметка «Зачем» | Вкладка «Зачем», запись дописывается к старой версии | Допиши причину к v1. Деталь не должна стать изменённой |
| 3 | Описание необязательно | Быстрое сохранение, в ленте «причина не указана» | Сохрани без текста, потом допиши причину |
| 4 | Отметки | Подписи в ленте: «в производстве», «в механизме» | Отметь версию, перезапусти окно |
| 5 | Дерево слева, карта снизу, поля «Было» и «Стало» | Новая раскладка, строка «Сейчас» в дереве, даты и паузы на карте | Щёлкни кружок: центр показывает ту же версию |
| 6 | Варианты | Кнопка «Новый вариант», своя папка, вторая линия на карте | Сделай «облегчённую», сохрани там версию, сравни в обеих папках |
| 7 | Сравнение между вариантами | «Было» из одного варианта, «Стало» из другого | Сравни v4 и v5 в 3D |
| 8 | «Есть новее» и «Взять отсюда» | Подсказка «вал v3, в основной v4», кнопка переноса | Обнови вал в варианте, старые версии остаются |
| 9 | Версия проекта | Кнопка «Версия проекта», список, что вошло | Сделай снимок, поменяй одну деталь, сделай второй |
| 10 | Группа изменений | Галочки при сохранении, одна причина на все детали | Сохрани две детали, причина видна у обеих |
| 11 | «Сделана из» | Новая деталь из старой, связь на карте | Создай «кронштейн усиленный» из кронштейна v3 |
| 12 | Граф проекта | Карта всех деталей, вариантов и заметок | Переход по кружку к детали |

Потом, по этапам проекта: файл `sldprt` со своим именем и аддин, дерево построения, MCP, сервер и утверждение, сборки, карта отклонений.

### Первый шаг подробно

Новых файлов данных нет, поэтому риск минимальный: окно только читает.

- `nonius-store`: список изменений между двумя версиями (`git diff --name-status`) и текст разницы для текстовых файлов.
- `nonius-app`: действия для окна и команд.
- `nonius-gui`: вкладки под 3D-видом.
- Текст сравнивается для `.md`, `.txt`, `.yaml`. Для PDF, DXF, STEP и PowerMill показываем «изменён» и размер.
- «Открыть» выкладывает копию файла версии во временную папку, чтобы служебный кэш нельзя было случайно испортить.

### Правый щелчок: открыть в нужной программе

Пожелание лидера. Делается отдельным шагом сразу после первого, потому что без него кнопка «Открыть» бедновата.

- Правый щелчок по файлу или детали: «Открыть», «Открыть в…», «Показать в папке».
- «Открыть в…» показывает программы, которые Windows знает для этого типа файла: CAD, CAM, слайсеры, программы для DXF и DWG. Список берётся из настроек Windows, сканировать диск не нужно. Запасной пункт — стандартное окно Windows «Открыть с помощью».
- Файл сохранённой версии открывается как копия. Правки в копии не меняют историю, и окно должно об этом предупредить. Файл из строки «Сейчас» открывается настоящий, из папки варианта.
- Работу с Windows держим в одном месте за общим действием `nonius-app`, чтобы позже добавить Linux. `unsafe` запрещён, поэтому берём чтение реестра через готовую библиотеку или системную команду.

## 9. Риски

| Риск | Что делаем |
|---|---|
| Проекты PowerMill не описаны в `LFS_EXTENSIONS`, большие файлы попадут прямо в git | Узнать, какие файлы он создаёт, дополнить список и шаблон `.gitattributes`. Для старых проектов нужна миграция |
| Совпадение имён `model.sldprt` в сборке | Проверить в SolidWorks до аддина |
| Номера версий при работе нескольких людей: другой мог занять номер, а мы его ещё не получили | Решить на этапе сервера. Один человек затронут не будет |
| Старые проекты с ручными ветками могут иметь двойные номера | Показывать коммит рядом и выбирать по нему |
| Сборка SolidWorks может открыть деталь из соседней папки варианта | Проверить на настоящей сборке на шаге 6 |
| Карта при сотнях версий | Сворачивать проходные версии, оставлять отмеченные |
