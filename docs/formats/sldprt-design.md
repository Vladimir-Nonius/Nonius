# Замысел конструктора и связи в файлах SolidWorks

О чём: что из «замысла» (дерево построения, размеры, уравнения, конфигурации, свойства, состав
сборки, внешние ссылки, чертежи) читается прямо из `.sldprt` / `.sldasm` / `.slddrw`, без
SolidWorks. Читать перед словами «что изменилось» не по геометрии и перед заменой `links.ps1`
чтением файла. Контейнер и распаковка потоков — в [sldprt-container.md](sldprt-container.md), масса
и превью — в [sldprt-display.md](sldprt-display.md), B-rep — в
[sldprt-parasolid.md](sldprt-parasolid.md).

Записано 13.11.2026. cadmpeg — коммит `a62e55e`. Ссылки `[cadmpeg sldprt.md …]` — их
`docs/formats/sldprt.md` (§ и строка), открытые вопросы — их `docs/formats/sldprt-open-items.md` по
номеру (`EV-16`), код — от `crates/cadmpeg-codec-sldprt/src/`. `[Nonius, N образцов]` — проверено
нашими разовыми скриптами на копиях файлов: 306 деталей, 40 сборок, 13 чертежей (`~$`-файлы
блокировки не в счёт) плюс пара `Test V1/V2`. Все образцы — в новом (блочном) контейнере, старого
OLE-контейнера среди них нет.

> **Воплощено в коде 15.11.2026** (`crates/nonius-sldprt/src/design/`, ветка `claude/sldprt-core`): §1 (`keywords.rs`), §2.1, §4.1, §5.1 (`manifest.rs`), §2.2–2.3, §6 (`props.rs`), §5.2 (`doubt.rs`). Прогон по 361 образцу: все читаются без пропусков за 0,3 с; признаки спорности: внешние ссылки — 52 файла, импорт — 37, старая версия — 7, несколько конфигураций — 4, производная деталь — 3 [Nonius, 361]. Двоичные секции (§3) не читаются.

## 0. Карта: где что лежит

| Что | Где | Вид | Читаемость |
|---|---|---|---|
| список операций, их имена, типы, id, размеры (как показаны) | `swXmlContents/KeyWords` | XML | легко |
| конфигурации, активная, «нужно перестроение», внешние ссылки | `swXmlContents/Features` (деталь) | XML | легко |
| состав сборки, положения, флаги компонентов | `swXmlContents/COMPINSTANCETREE` | XML | легко |
| свойства файла и конфигураций (ЕСКД), масса | `docProps/*.xml` | XML | легко |
| материал целиком (плотность, модули) | `swXmlContents/MATERIALTREE` | XML, UTF-16 | легко |
| точные значения размеров (м, рад) | `Contents/PMISemanticDataDB` | UnQLite + MessagePack | средне |
| операции, параметры, эскизы, уравнения | `Contents/Config-N`, `Config-N-ResolvedFeatures` | MFC CArchive | трудно, хрупко |
| сопряжения | `Contents/Config-N-MatesList` | CArchive | не разобрано (AS-01) |
| модели видов чертежа | `docProps/ISolidWorksInformation.xml` чертежа | XML | легко |

Главный вывод: всё, что нужно для слов «добавлено / удалено / переименовано / изменён размер /
сменился материал / масса», и состав сборки лежат в XML. Бинарь нужен только для точных чисел,
эскизов, уравнений и погашения — и там почти всё держится на подборе по образцам.

## 1. `KeyWords` — список операций

### 1.1 Где и как читать

- Поток `swXmlContents/KeyWords` (именно так, `W` заглавная). Есть в 306/306 деталях, 40/40 сборках,
  13/13 чертежах [Nonius, 359 образцов]. cadmpeg ищет его не по имени, а по корню XML `Keywords`
  [cadmpeg history/mod.rs:91]; в их тестах поток назван `Contents/Keywords` — на наших файлах такого
  имени нет.
- Перед `<?xml` стоит один байт: `0x86` (354 файла) или `0x85` (5 деталей) [Nonius]. cadmpeg знает
  только `0x86` [cadmpeg sldprt.md §2, таблица семейств]. Надёжно: пропустить байты до первого `<` в
  первых 8 байтах. Дальше UTF-8.
- Корень: `<Keywords id=… Name=…>`. `id` корня детали совпадает со временем создания файла
  `swFile/@swCreationTime` (unix-секунды) [Nonius, 308/308 деталей] и с первым словом `ModelStamps`
  [Nonius, 2 образца]. `Name` — не имя файла: в `Test V2.SLDPRT` там `Test V1`, в `Test V1` —
  прежнее имя документа [Nonius, 2 образца]; похоже на «обозначение в спецификации» (то же, что
  `swConfiguration/@swReference`).

### 1.2 Схема

| Элемент | Атрибуты | Что это |
|---|---|---|
| `Configuration` | `id`, `Name`, `Type="ConfigurationManager"`, `Description`, `Material` | конфигурация; `Material` — материал конфигурации |
| `Extrusion` | `id`, `Name`, иногда `Type`, `Dissectable`, `DissectableRoot`, `DissectableChildren` | вытягивание (бобышка или вырез) |
| `Cut` | то же | вырез |
| `Sketch` | `id`, `Name`, иногда `Type`, `Dissectable` | эскиз; у `Sketch id=5` — исходная точка |
| `Feature` | `id`, `Name`, `Type` | всё прочее: скругления, фаски, плоскости, папки, материал, уравнения, атрибуты |
| `Reference` | `id`, `Name`, `Type`, `Description` | в сборке и чертеже — экземпляр компонента |
| `Dimension` | `Name` (`D1`, `D2`…); текст — значение | размер операции, ребёнок операции |
| `Application` / `Keyword` | `Name`; текст | ключевые слова приложений (Simulation) — не операции |
| `Note`, `Quantity` | | редкие [cadmpeg sldprt.md §2, стр. 667] |

- Атрибут `Suppressed` («погашено») cadmpeg читает [cadmpeg history/mod.rs:277], но **ни в одном из
  359 наших файлов его нет** [Nonius]. Значит, погашение из `KeyWords` у нас не узнать (см. §3.6,
  §8).
- `SourceIndex` у `Configuration` cadmpeg тоже читает [cadmpeg history/mod.rs:128] — у нас 0 из 312
  конфигураций [Nonius].
- `id` — постоянный номер операции в документе (feature object ID). Тот же номер стоит в бинаре у
  имени операции и связывает их независимо от имени [cadmpeg sldprt.md §2, стр. 883]; он же —
  `swExtFeature/@swID` (§5). Новые операции получают номера больше прежних: в `Test V2` новые `2142`
  (эскиз) и `2151` (бобышка) при максимуме `2141` в V1 [Nonius].
- `DissectableChildren` — список `id` детей через разделитель; один ребёнок-эскиз у вытягивания —
  его профиль [cadmpeg sldprt.md §2, стр. 659]. `DissectableRoot` профилем не является [там же, стр.
  663].
- `id=-1` бывает у нескольких служебных узлов (`Sheet-Metal Master`, определения атрибутов) — не
  уникален [Nonius].
- Вложенность: у деталей и сборок дерево плоское (глубина 0), кроме `Application/Keyword` (5
  деталей) и `Quantity` (1); у чертежей `Sheet` содержит детей (§6) [Nonius]. Дерева построения
  (папки, кто чей родитель) в `KeyWords` нет.

### 1.3 Пример (сокращено из `Test V2`)

```xml
<Keywords id="1706104060" Name="Test V1">
  <Configuration id="0" Name="По умолчанию" Description="По_умолчанию"
                 Type="ConfigurationManager" Material="2024-T3"/>
  <Extrusion id="1910" Name="Бобышка-Вытянуть2" Dissectable="true"
             DissectableChildren="610" DissectableRoot="true">
    <Dimension Name="D1">5</Dimension></Extrusion>
  <Extrusion id="2151" Name="Бобышка-Вытянуть6" Type="Бобышка-Вытянуть"/>
  <Feature id="2127" Name="Скругление20" Type="Скругление">
    <Dimension Name="D1">12</Dimension><Dimension Name="D2">14.5</Dimension></Feature>
  <Feature id="34" Name="Уравнения" Type="Уравнения"/>
  <Sketch id="580" Name="Эскиз28" Dissectable="true">
    <Dimension Name="D1">&lt;MOD-DIAM&gt;42</Dimension></Sketch>
</Keywords>
```

### 1.4 Типы и локализация

- `Type` и имена по умолчанию **на языке SolidWorks**: «Скругление», «Фаска», «Бобышка-Вытянуть»,
  «Вырез-Вытянуть», «Плоскость», «Уравнения», «Материал SOLIDWORKS», «Листовой металл», «Резьба»,
  «Линейный массив»… [Nonius, 308 деталей]. Английские токены встречаются вперемешку:
  `ConfigurationManager`, `Sheet-Metal Master`, `Multi_CAD_Imported`, `Point`; имена папок
  `Favorites`, `History`, `Selection Sets` — английские при русском `Type` [Nonius].
- Значит, распознавать операцию по `Type` надо словарём «русский + английский токен → вид». cadmpeg
  опирается на английские токены (`EquationDriven` для узла уравнений [cadmpeg sldprt.md §2, стр.
  1260], `Boss-Extrude`, `Helix/Spiral` [там же, стр. 1058]) — на русских файлах это не сработает:
  узел уравнений у нас `Type="Уравнения"`.
- У части `Extrusion`/`Cut`/`Sketch` нет `Type` («бесклассовые», 190 `Extrusion` и 257 `Sketch` из
  308 деталей) — вид берётся из имени тега [Nonius]. Различать «бобышку» и «вырез» без `Type` по
  тегу можно (`Cut`), но вытягивание с `moCut_c` в бинаре — вырез, даже если тег `Extrusion`
  [cadmpeg sldprt.md §2, стр. 671].
- Служебные узлы (папки, свет, датчики, «Связь проектов», атрибуты с именами-GUID) есть в каждой
  детали; их роли задаются раскладкой номеров `id` (1 — примечания, 2/3/4 — Спереди/Сверху/Справа, 5
  — исходная точка…) [cadmpeg sldprt.md §2, стр. 1252–1274]. Для слов о изменениях их надо
  отбрасывать: тип из списка служебных или имя-GUID.

### 1.5 Порядок

- Порядок элементов — **не порядок дерева**. На всех 361 файле верхние элементы отсортированы по
  (тег, `id` как строка): `Configuration` → `Extrusion` → `Feature` → `Sketch`, внутри `"1910" <
  "2114" < "53"` [Nonius]. cadmpeg: «порядок записи, не перестроения» [cadmpeg sldprt.md §2, стр.
  681].
- Порядок перестроения cadmpeg строит топологической сортировкой по ссылкам «родитель/зависимость»,
  несвязанные — в порядке записи [там же]. Для Nonius проще: числовой `id` ≈ порядок создания (не
  порядок в дереве после перетаскивания) [не проверено].

### 1.6 Значения размеров

- Текст `Dimension` — **то, что показано на экране**: число в единицах документа, без единицы,
  округлённое до точности показа, хвостовые нули отброшены [cadmpeg sldprt.md §2, стр. 1298]. В
  `Test V1` `SW_UnitsLinearDecimalPlaces=2`, текст `14.5`, `8` [Nonius].
- Приставки: `R2` (радиус), `<MOD-DIAM>42` (диаметр), `45°` (угол, в градусах). Частые значения на
  наших образцах: `45°` 172 раза, `R1` 94, `<MOD-DIAM>10` 64 [Nonius]. Бывают дроби дюймов
  (`17/32"`) и `TXD…` — форматированный текст [cadmpeg sldprt.md §2, стр. 1164, 1298].
- Литералы с единицей (`mm`, `in`, `ft`, `um`…) и множители к мм — [cadmpeg sldprt.md §2, стр.
  1180].
- Единицы документа: `SW_UnitsLinear` в `ISolidWorksInformation.xml` (`0` — мм) [cadmpeg sldprt.md
  §8; Nonius]. Без них `11` — то ли 11 мм, то ли 11 дюймов.
- Округление скрывает малые изменения: при двух знаках 12.001 → 12.004 в обеих версиях записано
  `12`. Точные значения — §3.6.
- Размеры — только активной конфигурации [cadmpeg sldprt.md §2, стр. 1304]. Уравнение, которое ведёт
  размер, в `KeyWords` не хранится — только результат [там же, стр. 1262].

### 1.7 Конфигурации в `KeyWords`

- Перечислены **все** конфигурации, не только активная: в 4 деталях- сварных конструкциях — две, `По
  умолчанию<Как обработанный>` (`id=0`) и `По умолчанию<Как сварной>` (`id=3`) [Nonius]. Какая
  активна — из манифеста (§2.1).
- `id` конфигурации — номер `N` её потоков `Contents/Config-N…` и `docProps/Config-N-Properties.xml`
  [cadmpeg sldprt.md §2, стр. 1174; §8.1]. У неактивной `id=3` в наших 4 файлах есть только
  `Config-3-Properties.xml`, бинарных `Config-3*` нет [Nonius].

## 2. Манифест и свойства

### 2.1 `swXmlContents/Features` (детали)

XML в пространстве `http://www.solidworks.com/sw2003/schema`, корень `swSolidWorks` с `swVersion`
[cadmpeg sldprt.md §2; Nonius, 308 деталей]:

| Элемент | Атрибуты | Смысл |
|---|---|---|
| `swHeader/swFile` | `id`, `swDocType`, `swCreationTime`, `swPath` | первый — сам документ (путь при сохранении); дальше — документы внешних ссылок |
| `swModelList/swModel` | `id`, `swName`, `swConfigurationName`, `swConfigurationId`, `swLastModifiedStamp`, `swConfigurationFlags`, `swFileRef` | модель = документ × конфигурация |
| `swConfigurationList/swConfiguration` | `id`, `swName`, `swID`, `swReference`, `swMostRecentConfiguration`, `swConfigurationNeedsUpdate`, `swDefeatureConfiguration`, `swModelRef` | конфигурации документа |
| `swExtFeatureList/swExtFeature` | `id`, `swName`, `swFeatureType`, `swConfigurationName`, `swSuppressed`, `swModelRef`, `swID` | операции с внешней ссылкой (§5) |

- Ровно одна конфигурация с `swMostRecentConfiguration="YES"` — активная, её `swID` = `id` в
  `KeyWords` [cadmpeg sldprt.md §2, стр. 1041; Nonius, 308/308].
- `swConfigurationNeedsUpdate="YES"` — конфигурация не перестроена с последней правки. У нас: 304
  детали «NO», 4 — «NO, YES» (неактивная сварная конфигурация) [Nonius]. Это не свидетельство
  свежести сохранённых кэшей (масса) [cadmpeg DI-03].
- `swConfiguration/@swReference` = свойство `SW-BOM Part Number` («обозначение в спецификации»)
  [Nonius, 2 образца].
- `swLastModifiedStamp` растёт с каждой правкой: 8302 → 8316 между `Test V1` и `V2`; то же число —
  второе слово `ModelStamps` [Nonius]. Дёшево отличает «файл пересохранён без правок» от «модель
  менялась» — проверить на большем числе образцов.
- `swVersion`: 16000 (296), 18000 (6), 9000 (6) [Nonius]. Совпадает с папкой `_MO_VERSION_<n>/` того
  же файла. Граница 12000 меняет разметку бинаря (§3.8).

### 2.2 `docProps/ISolidWorksInformation.xml`

Свойства «по умолчанию», корень `Properties` в пространстве `…/SolidworksInformation-properties`,
`propertySection` с `fmtid`, `property name pid` с типизированным ребёнком `vt:*` [cadmpeg sldprt.md
§8.1]. Полезное [Nonius, 308 деталей]:

| Свойство | Пример / смысл |
|---|---|
| `SW-Created Date`, `SW-Last Saved Date` | текстом, на языке SolidWorks |
| `SW-Last Saved By` | имя учётной записи — **личные данные**, не показывать |
| `SW-Folder Name`, `SW-File Name` | папка и имя при сохранении |
| `SW-Configuration Name` | активная конфигурация |
| `SW-HasDesignTable` | `1` — есть таблица параметров (у нас везде `0`) |
| `SW-BOM Part Number` | обозначение в спецификации |
| `SW_UnitsLinear`, `SW_UnitsLinearDecimalPlaces`, `SW_UnitsAngular…` | единицы и точность показа |
| `SW-MassProp-Config-N` | сохранённые масс-свойства конфигурации `N` (14 чисел через запятую) |
| `SW-Config-Model-View-Sheet-List` | только у чертежа — модели видов (§6) |

`SW-MassProp-Config-N`: центр масс x/y/z (м), объём (м³), площадь (м²), масса (кг), шесть моментов
инерции [cadmpeg sldprt.md §8.1]. cadmpeg пишет «шесть знаков после точки»; у `Test V2` — 16 знаков,
только два последних поля `1.000000, 0.000000` [Nonius] — разбирать как обычные числа. Подробнее — в
[sldprt-display.md](sldprt-display.md).

### 2.3 `custom.xml` и `Config-N-Properties.xml` (свойства ЕСКД)

- `docProps/custom.xml` — свойства документа (вкладка «Настройка»). У нас почти пустые: только
  служебный `pid=1` (кодовая страница 65001) [Nonius].
- `docProps/Config-N-Properties.xml` — свойства конфигурации `N`, корень `ConfigProperties`
  (`http://www.solidworks.com/config-properties`), две секции: DocumentSummaryInformation и
  UserDefinedProperties; брать свойства из второй [cadmpeg sldprt.md §8.1]. Шаблон ГОСТ даёт
  [Nonius, `Test V2`]: `Обозначение`, `Наименование`, `Масса`, `Материал`, `Раздел`, `Типоразмер`,
  `Заготовка`, `Вид_документа`, `Код_документа`, `Лит`, подписи `п_Разраб`, `п_Пров`… с датами,
  `а_Инв_№…`.
- Форма свойства: `<property name="Масса" pid="5" IsEquation="False" TypeID="30">`
  `<vt:lpstr>1.21</vt:lpstr><FPVals><vt:lpstr>&lt;$5$1.2131691352424556$&gt;</vt:lpstr></FPVals>`.
  `vt:lpstr` — показанное значение, `FPVals` — вычисленное с полной точностью. Формула лежит в
  отдельном свойстве без имени с `pid = 0x1000000 + pid`: `"SW-Mass@@По умолчанию@Test V2.SLDPRT"`
  [Nonius, 2 образца]. Сохранённое значение может быть устаревшим [cadmpeg DI-03, DI-04].
- В `Test V1`→`V2` масса 1.2226 → 1.2132 кг, материал `2024-T3` без изменений [Nonius].

### 2.4 `MATERIALTREE` и `OpenTime.xml`

- `swXmlContents/MATERIALTREE` — UTF-16 с BOM, `mstns:materials`: `material name="solidworks
  materials|2024-T3"` с `physicalproperties` (`DENS` 2780, `EX`, `NUXY`, `SIGYLD`… в СИ) [Nonius,
  31 из 308 деталей — поток необязательный]. Имя материала надёжнее брать из `Configuration/@Material`.
- `docProps/OpenTime.xml` — время открытия (`count`, `TotalFileOpenTime`, `FileOpenTime="0:47"`)
  [Nonius, 303 детали]. Меняется от открытия к открытию — не считать это правкой.

### 2.5 Старый контейнер (OLE / CFB)

Среди наших образцов нет ни одного; всё ниже — [cadmpeg sldprt.md §8.1]. Те же данные лежат
корневыми потоками: свойства по умолчанию — `ISolidWorksInformation`, свойства документа —
`\005DocumentSummaryInformation` (формат MS-OLEPS: заголовок, секции по FMTID, словарь имён PID 0,
кодовая страница PID 1), свойства конфигурации — `Config-0-Properties`. Если у `Configuration` в
`KeyWords` нет `id`, а конфигурация одна — ей принадлежит `Config-0-Properties`; при других
количествах владелец не определён [cadmpeg DI-04]. Сборка в старом контейнере не имеет
`swXmlContents`, значит и `COMPINSTANCETREE` [cadmpeg AS-02].

## 3. Бинарь: MFC CArchive

### 3.1 Потоки

| Поток | Что внутри |
|---|---|
| `Contents/Config-N` | объект `moPart_c`: единицы, материал, тела, менеджер уравнений `moRelMgr_c`, папки, виды [cadmpeg sldprt.md §2.3, стр. 1855–1871] |
| `Contents/Config-N-ResolvedFeatures` | операции с параметрами, эскизы, ссылки на грани, вложенные Parasolid-профили [там же, стр. 369] |
| `Contents/CnfgObjs`, `CMgr`, `Config-N-ModelHeader`, `Definition` | тот же формат объектов; `CMgr` — менеджер конфигураций [там же, §2.2] |

### 3.2 Как устроена сериализация

[cadmpeg sldprt.md §2.2; carchive/mod.rs:1-8]

- Объект = метка класса + тело. Длины у тела нет: пропустить объект, не зная разметки его класса,
  нельзя.
- Метка `ff ff`, u16 схема, u16 длина, ASCII-имя — новый класс (дальше его объект). `0x8000 | i` —
  объект класса с номером `i` в карте. `0x7fff` + u32 — для больших номеров. `00 00` — пустой
  объект.
- Классы и объекты делят один счётчик карты. Ссылка на уже записанный объект — его номер (u16 с
  нулевым 15-м битом или `ff 7f` + u32).
- `Config-N` и `Config-N-ResolvedFeatures` — **одна карта**: `ResolvedFeatures` начинается с u32 «на
  чём кончился счётчик `Config-N`» и может ссылаться на его объекты. Читать второй без первого
  нельзя.
- Строки — `ff fe ff`, байт длины (`ff` → u16), UTF-16LE.
- `suObList` — список MFC: u16 количество и объекты.
- Именованный объект открывается `moNodeName_c` (имя), затем заголовок: u32 по смещению +8 после
  имени — тот самый `id` из `KeyWords` [cadmpeg sldprt.md §2.3, стр. 1643–1653]. У операций дальше
  «блок операции»: входы (ссылки на объекты), номера версий и даты `год×1000+день`, FILETIME [там
  же, стр. 1655–1690; EV-06].

### 3.4 Что реально извлекается

- **Параметры.** `moLengthParameter_c` / `moAngleParameter_c` / `moScalerParameter_c`: заголовок с
  именем (`D1`) и `id`, u16 `0`, f64 значение, 35-байтный хвост [cadmpeg sldprt.md §2.3, стр. 1843].
  Длины — в метрах, углы — в радианах [там же, §2, стр. 1158]. Число 0.008 → 0.012 у
  `D1@Скругление20` между `Test V1/V2` видно и в PMI (§3.6) [Nonius].
- **Значения по конфигурациям.** `Config-N-ResolvedFeatures` даёт вычисленные параметры и состояние
  операций конфигурации `N` [cadmpeg sldprt.md §2, стр. 1168–1176].
- **Вытягивание.** Глубина, направление, тип окончания (`moEndSpec_c`: 0 — на глубину, 1 — насквозь,
  2 — до следующей, 3 — до вершины, 4 — до грани/поверхности, 5 — от грани со смещением, 6 — от
  средней плоскости, 9 — насквозь в обе стороны) [cadmpeg sldprt.md §2, стр. 693–705; §2.3, стр.
  2006]. Профиль — эскиз-ребёнок или вложенный Parasolid-поток со схемой `SCH_SW_33103_11000` [там
  же, стр. 369].
- **Эскизы.** `sgSketch`: точки, отрезки, дуги — записи внутри объекта, «ручки»
  `sgPointHandle`/`sgLineHandle`/`sgArcHandle` указывают на них по номеру; координаты f64 [cadmpeg
  sldprt.md §2.3, стр. 1903–1958]. Профиль эскиза хранится ещё и готовым Parasolid-телом (лист) —
  его читать проще, чем записи [там же, стр. 1944].
- **Ссылки на грани и рёбра** — постоянные идентичности: цепочки «какая операция породила грань»
  (`moFR_c`: `id` операции + метка времени) [cadmpeg sldprt.md §2.3, стр. 1789–1808].

### 3.5 Взаимосвязи эскиза

[cadmpeg sldprt.md §2, стр. 793–819]

- Таблица взаимосвязей идёт после записей эскиза. Строка: u32 код, `02 00`, u16 флаг, `00 00 fe ff
  00 00`, ручки операндов.
- Коды 1–27: расстояние, угол, радиус, горизонталь, вертикаль, касательность, параллельность,
  перпендикулярность, совпадение, концентричность, симметрия, середина, пересечение, равенство,
  диаметр, смещение, фиксация, углы дуги 90/180/270, крайние точки дуги, точки по
  горизонтали/вертикали, коллинеарность. 28–85 — прочие (сплайны, 3D, блоки, пазы, массивы).
- Нейтральный смысл известен для 4–9, 11–14, 25–28 при флаге 0. Коды 29–32, 36–41, 43–85 не
  разобраны — **DI-08**; выше 85 — **DI-09**; смысл флага — DI-45; рамка таблицы — DI-47.
- Восемь «групп взаимосвязей» и часть полей заголовка эскиза неизвестны — **EV-16**.

### 3.6 Точные значения размеров

- **`Contents/PMISemanticDataDB`** — база UnQLite, записи MessagePack с ключами `cadText`,
  `dimText`, `dimItems` (`DimSemData`: `dimSubType` =
  `Linear`/`Diameter`/`Radial`/`Angle`/`Ordinate`, `value` f64, `valPrecision`), `supressState`,
  `isReferenceOnly` [cadmpeg sldprt.md §2, стр. 1298; pmi.rs:605; Nonius]. `cadText =
  "<размер>@<операция>"` (`D1@Скругление20`) — связь с `KeyWords`. Длины — метры, углы — радианы.
- Поток есть в 253 из 306 деталей; в `Test V1` — 28 записей = 28 размеров `KeyWords` [Nonius].
  `D1@Скругление20`: 0.008 → 0.012 м в `V1/V2` [Nonius].
- Правило cadmpeg: запись PMI даёт точное значение, если совпадает с текстом `KeyWords` после
  округления (множители 0.001 / 0.0254 / 1, до 1e-9) [cadmpeg sldprt.md §2, стр. 1298].
- Нет записи PMI — точное f64 можно взять у уравнений (§3.7), со сложными правилами согласия [там
  же, стр. 1300–1306].
- Поле `supressState` в записи — возможно, погашение размера/операции [не проверено].

### 3.7 Уравнения и глобальные переменные

[cadmpeg sldprt.md §2, стр. 1142–1154, 1260–1306; §2.3, стр. 1899]

- Менеджер `moRelMgr_c` — в `Contents/Config-N` каждой конфигурации: u16 число строк, объекты
  `moRelation_c`. Текст строки — UTF-16 как в окне «Уравнения»: `"D1@Эскиз1" = "Ширина" * 2`,
  `"Ширина" = 40`, апостроф — комментарий. Имя с `@` — размер, без `@` — глобальная переменная.
- Каждая сторона — токены (строка + 4 слова: вид, начало, конец, род). Ссылка на размер несёт его
  значение f64 (м/рад/штуки), на переменную — её значение текстом.
- Узел «Уравнения» в `KeyWords` — контейнер глобальных переменных (`Type="Уравнения"` у нас,
  `EquationDriven` у cadmpeg).
- Режим «градусы/радианы» для тригонометрии — байт в настройках после строк; границу настроек не
  умеют найти надёжно (**DI-02**, **DI-43**).
- Сохранённые значения могут быть входом, а не результатом, и в потоке неактивной конфигурации могут
  лежать значения активной (**DI-42**).
- Разбор `Config-N` доходит до уравнений не всегда: шаблоны промежутков по версиям, 34 потока
  останавливаются на уравнениях, ни один из 37 потоков версий 10000–12000 не дочитан (**EV-19**).
- У нас уравнения есть в 1 детали из 306 (`"мм"=-2.5784` — глобальная переменная), в остальных
  менеджер пуст [Nonius]. Для слова «изменено уравнение» хватит сравнить **тексты** строк — значения
  не нужны.

### 3.8 Насколько это хрупко

- Разметка классов подобрана по образцам, не по описанию: для многих классов известна только часть
  полей, остальное — «столько-то байт» (EV-06 … EV-23). Неизвестный класс останавливает чтение
  потока — дальше объектов не видно.
- Открытые: тело эскиза — **EV-16**; вытягивание (блок размещения, двухсторонние формы, ICE без
  меток) — **EV-17**; ссылки «в контексте» — EV-18; `Config-N` (настройки оформления, резьбы,
  уравнения, версии ниже 14000) — **EV-19**; листовой металл — EV-23; прочие семейства операций
  `KeyWords` без нейтрального смысла — **DI-14**.
- Диалекты по `swVersion`: ниже 12000 отступ кода формы операции 4 байта, с 12000 — 8 [cadmpeg
  dialect.rs:219]; поля появляются с 11000, 13000, 14000, 15000, 16000, 17000, 18000, 19000 [cadmpeg
  sldprt.md §2.3 — «в файлах `swVersion` от …» по всему разделу]. Наш разброс: 9000, 16000, 18000.
- Вывод для Nonius: бинарь — только как необязательное уточнение (точное число, эскиз), с честным
  «не прочитано». Слова строить на XML.

### 4.1 `swXmlContents/COMPINSTANCETREE`

[cadmpeg sldprt.md §11.1–11.2; assembly.rs:1-15; Nonius, 40 сборок]

Есть в 40/40 сборках, `swXmlContents/Features` у сборок нет. Тот же корень `swSolidWorks`:

| Элемент | Атрибуты | Смысл |
|---|---|---|
| `swHeader/swFile` | `id`, `swDocType` (`ASSEMBLY`/`PART`), `swCreationTime`, `swPath`, `swImportedPath` | все документы; первый — сама сборка |
| `swModelList/swModel` | `id`, `swName`, `swConfigurationName`, `swConfigurationId`, `swFileRef`, `swBoundingBox` (м), `swLastModifiedStamp`, `swImportedName` | документ × конфигурация |
| `swModel/swReference` | `id`, `swName`, `swReferenceNumber`, `swComponentName`, `swID`, `swModelRef`, `swConfigurationName`, `swConfigurationId`, `swTransform`, флаги | экземпляр компонента в этой модели |

- Имя экземпляра `<swName>-<swReferenceNumber>` (`пин-2`). `swReference/@swID` = `id` элемента
  `Reference` в `KeyWords` сборки, с тем же именем [Nonius, 2 сборки смотрели глазами]. В `KeyWords`
  — только экземпляры верхнего уровня (722 против 795 в деревьях) [Nonius].
- `swConfigurationName` у экземпляра бывает «имя + описание в кавычках» (`По умолчанию
  "По_умолчанию"`) и `swConfigurationId="-1"` — в сборке `swVersion=9000` [Nonius, 1 сборка].
- Модели — ациклический граф: подсборка может стоять несколько раз; дерево экземпляров = все пути от
  корневой модели активной конфигурации. `swName` модели подсборки — имя верхней сборки, имя
  документа брать из `swFile/@swPath` [cadmpeg sldprt.md §11.1].

### 4.2 Положение `swTransform`

16 чисел, матрица 4×4 по строкам для вектора-строки `p' = p·M`: строки 0–2 — поворот, строка 3 —
перенос в метрах и `1`. Относительно сборки, содержащей `swReference`; мировое — произведение по
пути [cadmpeg sldprt.md §11.2]. У компонентов, которые ведут сопряжения пути / цепи, сохранённое
положение может не совпадать с решённым (до 85 мм) — **AS-03**.

### 4.3 Сопряжения, встроенные и виртуальные компоненты

- `Contents/Config-N-MatesList` — сопряжения, классы `moMate…` (`moMateCoincident`,
  `moMateConcentric`, `moMateDistanceDim_c`, `moMateParallel`, `moMateInPlace`…); операнд —
  `<экземпляр>@<сборка>` и строка `SurfIdRep` грани. Разметка записей неизвестна — **AS-01**
  [cadmpeg sldprt.md §11.3]. У нас `moMate*` в 37 из 40 сборок [Nonius].
- `ImportedComp/<имя>` и потоки на `.sldprt`/`.sldasm` — целые вложенные документы (импорт STEP); у
  таких `swFile` есть `swImportedPath` (исходный `.stp`), `swPath` ведёт на несуществующий
  `…stp.SLDASM` [cadmpeg §11.4; Nonius, 83 файла].
- Виртуальный компонент: `VirtualComp/<имя>`, имя документа `<имя>^<сборка>`; `swPath` у нас ведёт
  во временную папку SolidWorks `…\Temp\swx…\VC~~\…` — по нему файла нет и не будет [cadmpeg §11.5;
  Nonius, 37 виртуальных файлов].
- Старые сборки (OLE, до 12000): нет `COMPINSTANCETREE`, где экземпляры — неизвестно, кандидат
  `Contents/Config-0` — **AS-02**. Parasolid-потоки в самой сборке (элементы сборки, кэш граней) —
  AS-04.

### 4.4 Поиск файлов компонентов

- cadmpeg файлы не ищет: путь из `swPath` лишь записывается как «внешний документ» [cadmpeg
  assembly.rs:677].
- SolidWorks ищет по своему порядку (справка «Search Routine for Referenced Documents») — по памяти,
  **[не проверено]**: уже открытые документы → папки из настроек «Ссылочные документы» → путь
  относительно родительской сборки (та же структура папок) → папка родителя → сохранённый абсолютный
  путь → спросить человека.
- Для Nonius достаточно: (1) `swPath` как есть, если файл там; (2) то же имя в папке сборки и её
  подпапках разбираемой папки; (3) иначе — «не нашёл», не гадать. Виртуальные и импортированные — не
  искать, они внутри сборки. На наших копиях: из 265 обычных путей 263 существуют по сохранённому
  абсолютному пути (оригиналы на месте), 2 — нигде [Nonius].

### 4.5 Сравнение с `links.ps1`

`links.ps1` зовёт `GetDocumentDependencies2(файл, false, false, false)` — прямые ссылки, без обхода
вглубь и **без поиска**, т.е. те же сохранённые пути; `links.rs` раскладывает их, `intake/units.rs`
и `plan.rs` сопоставляют путь целиком (в нижнем регистре) с файлами папки [Nonius
`crates/nonius-solidworks/src/links.ps1`, `links.rs`; `crates/nonius-app/src/intake/units.rs`].

| | `links.ps1` | чтение файла |
|---|---|---|
| нужен SolidWorks | да (Windows, лицензия, запуск) | нет |
| состав сборки (прямые) | пути | `swFile/@swPath` + модели, конфигурации, количество, флаги, положения |
| чертёж → модель | пути | `SW-Config-Model-View-Sheet-List` (§6) |
| деталь → внешние ссылки | пути | `swExtFeatureList` + `swFile` (§5) |
| перенесённая папка | путь не совпадёт | то же; но имя файла под рукой — можно искать по имени |
| виртуальные / импортированные | (не проверяли) | видно флагом и `swImportedPath`; искать не надо |
| старые OLE-сборки | работает | **нет** `COMPINSTANCETREE` (AS-02) |

Вывод: для файлов нового контейнера `COMPINSTANCETREE` + `Features` + свойство чертежа полностью
заменяют `links.ps1` и дают больше (конфигурация компонента, погашение, «исключить из спецификации»,
число экземпляров). Не хватит: старых сборок (AS-02) и «поиска как в SolidWorks» — его надо написать
самим (§4.4). Для старых файлов `links.ps1` оставить запасным путём.

| есть `swExtFeature` | `Features` | форма зависит от другого файла, который мог измениться |
| `SW-HasDesignTable=1` | `ISolidWorksInformation.xml` | размеры ведёт таблица Excel |
| строки в `moRelMgr_c` | `Config-N` | размеры ведут уравнения (иногда из внешнего файла) |
| несколько конфигураций | `KeyWords`, `Features` | размеры и масса — только активной; неактивные могут быть без потоков |
| `swVersion` ниже 12000 или OLE-контейнер | `Features` / заголовок | другой диалект, бинарь хуже читается, нет части XML |
| импорт (`Multi_CAD_Imported`, `MBimport`) | `KeyWords`, `Features` | дерева нет, размеров нет — только форма |
| `swExtFeature` вида `Stock` | `Features` | деталь — производная от другой (у нас — от шестерни из Toolbox) |

Про `Stock` [Nonius, 3 файла]: это ровно те детали, у которых беглая форма по сетке не сошлась с выгрузкой SolidWorks (в сетке 337 граней и 121 мм, SolidWorks выгружает 79 граней и 86 мм). В их списке операций — базовая деталь из библиотеки, «Тело-Переместить/Копировать» и вырезы поверх: в файле лежит сетка не только итогового тела. Признак `Stock` ловит все три случая; скрытых тел как таковых в `KeyWords` и манифесте не видно.

## 6. Чертежи `.slddrw`

[Nonius, 13 чертежей; cadmpeg о чертежах не пишет]

- `swXmlContents/KeyWords` есть во всех 13. Дети корня: служебные `Feature` (папки, точки привязки
  таблиц, плоскости), `Reference` — экземпляры моделей в видах (`пин-1` … `пин-11`), `Sketch`,
  `Note`, `Dimension`, и `Sheet`:

```xml
<Sheet id="2" Name="Лист1" Type="Лист">
  <View Name="Чертежный вид1" Description="По умолчанию">пин.sldprt</View>
  <PaperSize Description="12">USER_SIZE</PaperSize>
  <ScaleNumerator>2.000000</ScaleNumerator><ScaleDenominator>1.000000</ScaleDenominator>
  <TemplateName>temp_a3.slddrt</TemplateName>
</Sheet>
```

  `View` — имя вида, конфигурация (`Description`) и **только имя файла** модели, без пути.
  Верхнеуровневые `View` с именами `*Спереди`, `*Изометрия`… — именованные виды модели.
- Полный путь модели — в `docProps/ISolidWorksInformation.xml`, свойство
  `SW-Config-Model-View-Sheet-List`. Точный вид [Nonius, 13 чертежей, от 1 до 3 видов]:
  `<число видов>:@@`, дальше на каждый вид пять ячеек через `@` —
  `<конфигурация>@0@<полный путь>@<вид>@<лист>`; между видами один `@`, не два. Пример:
  `2:@@По умолчанию@0@C:\…\вал.SLDPRT@Чертежный вид1@Лист1@По умолчанию@0@C:\…\вал.SLDPRT@Разрез A-A@Лист1`.
  Смысл второй ячейки (`0`) неизвестен. Есть у 13/13 [Nonius].
- Ловушка имён: `шестерня.SLDDRW` ссылается на `шестерня исправленная.SLDPRT`, `швп чертёж.SLDDRW` —
  на `швп.SLDPRT` [Nonius]. Сопоставление по имени ошибётся, по ссылке — нет.
- Пути есть и в бинарных `Header2`, `Contents/Definition`, `Contents/VBLists` (UTF-16; полный путь в
  `Header2` у 13/13), но там попадаются посторонние: в обоих просмотренных чертежах первым стоит
  путь чужой детали, видимо из шаблона [Nonius] — брать свойство, не бинарь.
- `swXmlContents/CustomProperties` — не XML; `swXmlContents/xmlstream-2` — в 1 чертеже, не
  разбирали.

## 7. Применение в Nonius

> **Воплощено 15.11.2026**: пункты 1–3 ниже — `nonius_core::design::diff` (сравнение по `id`: добавлено, удалено, переименовано, размер изменился; служебные узлы помечены). Проверено на `Test V1` → `Test V2`: ровно три изменения — добавлены `Эскиз49` (id 2142) и `Бобышка-Вытянуть6` (id 2151), у `Скругление20` D1 8 → 12; служебных изменений нет [Nonius, 1 пара]. Размеры сравниваются по показанному тексту; точные значения PMI, материал, масса, уравнения, свойства, сборка (пункты 2, 4–7) в сравнение пока не входят.

Сравнение двух версий детали по XML — дёшево (распаковать 3–4 потока), без SolidWorks. Пример `Test
V1` → `Test V2` [Nonius]:

- добавлено: `Бобышка-Вытянуть6` (id 2151), `Эскиз49` (id 2142);
- изменено: `Скругление20` D1: 8 → 12 (PMI: 0.008 → 0.012 м);
- масса: 1.22 → 1.21 кг (сохранённая), материал тот же.

Как строить слова:

1. Сопоставлять операции по `id`, не по имени и не по порядку. Тот же `id`, другое имя —
   «переименовано» (что `id` переживает переименование — **[не проверено]**). Нет `id` в старой —
   «добавлено Скругление5», нет в новой — «удалено».
2. Размеры — по (`id` операции, `Name` размера): «в Вырез-Вытянуть3 D1: 10 → 12». Сравнивать точные
   значения PMI, если есть, иначе текст `KeyWords`; единицы — из `SW_UnitsLinear`. Имена `D1`
   человеку мало говорят — показывать вид операции и приставку (`R`, `⌀`, `°`): «скругление R8 →
   R12».
3. Отбрасывать служебные узлы (папки, свет, атрибуты-GUID, плоскости по умолчанию) и узлы без
   размеров, если не добавлены/удалены.
4. Материал — `Configuration/@Material`; масса — `Config-N-Properties` (`FPVals`) или
   `SW-MassProp-Config-N`, с оговоркой «сохранённое».
5. Уравнения — сравнить тексты строк `moRelMgr_c` («изменено уравнение "Ширина" = 40 → 45»), только
   если бинарь дочитан; иначе молчать.
6. Свойства ЕСКД — `Обозначение`, `Наименование` из `Config-N-Properties.xml`: «изменено
   обозначение».
7. Сборка: состав по `swReference` (по `swID`/имени экземпляра), смена конфигурации компонента,
   «погашено» по `swSuppressed`, сдвиг по `swTransform`.

Ограничения:

- «Погашено» для операций детали не читается: `Suppressed` в `KeyWords` у нас не встречается, где
  SolidWorks хранит погашение — не найдено (§8).
- Размеры только активной конфигурации; округлены до показа.
- Операция без размеров (зеркало, массив, импорт) меняется «молча»: изменения ссылок на грани,
  профиля эскиза, условий окончания по XML не видны.
- `Type` локализован — словарь видов операций двуязычный.
- Перестановка в дереве не видна (порядок `KeyWords` — сортировка).
