# Форматы CAD: база знаний

Что Nonius знает о файлах SolidWorks и о том, как их читать: без
SolidWorks (прямо из байтов) и через SolidWorks (COM). Написано для
следующих агентов и людей, которые будут менять `nonius-sldprt`,
`nonius-solidworks` или добавлять чтение новых форматов.

Начато 13.11.2026.

## Откуда знания

1. **Свои файлы.** `nonius-sldprt` разобран по настоящим файлам: сетка
   показа, метки `ModelStamps` / `DLUpdateStamp`, превью.
2. **cadmpeg** — открытый конвертер CAD-форматов на Rust,
   <https://github.com/cadmpeg/cadmpeg>. Код под Apache-2.0, документация
   под CC BY 4.0. Наши файлы пересказывают его спецификацию
   `docs/formats/sldprt.md` и код по коммиту `a62e55e` (13.11.2026) с
   указанием авторства — CC BY 4.0 это разрешает. Ссылки вида
   `[cadmpeg tessellation.rs:879]` — пути от корня их репозитория на этом
   коммите.
3. **Открытые источники о SolidWorks API** — xCAD, справка SolidWorks,
   DriveWorks; ссылки в [solidworks-automation.md](solidworks-automation.md).

## Пометки у фактов

- `[cadmpeg …]` — из их спецификации или кода; у нас не проверено, если не
  сказано иное.
- `[Nonius …]` — из нашего кода или проверено на наших образцах (с числом
  образцов).
- `[не проверено]` — догадка или вывод, который ещё надо подтвердить.

Если cadmpeg и наши образцы расходятся — верим образцам и пишем об этом.

## Правила пополнения

- Чистый разбор: только свои файлы и файлы с правами, наблюдение байтов,
  публичные документы. Никаких SDK SolidWorks и декомпиляции программ.
  Подробнее — [practices.md](practices.md), раздел 9.
- Неизвестное не выдаём за факт: пишем в «Открытые вопросы» своего файла.
- Новые знания — в файл по теме; файл разросся — делить по темам, как код.
- Имена людей и пути с машины человека в эти файлы не попадают.

## Главное в двух словах (проверено на ~360 наших файлах)

- Все наши файлы — новый блочный контейнер: по сути ZIP с подменёнными
  сигнатурами, в конце настоящий центральный каталог. Старых OLE-файлов
  среди образцов нет.
- Беглая форма по свежей сетке сходится со STEP в пределах 0,5 % у 86 из
  90 деталей; устаревшая сетка (метка `DLUpdateStamp` меньше
  `ModelStamps`) врёт до сотен процентов — отказ по меткам оправдан.
- Сохранённая SolidWorks масса (`SW-MassProp-Config-N`) обычно округлена до
  показа (2 знака в СИ) — как эталон объёма почти бесполезна.
- Точная форма (Parasolid) лежит только для активной конфигурации.
  Поверхности точные, но рёбра пересечений хранятся ломаной с ошибкой
  до миллиметров — читать её «как есть» для сравнения с допуском 0,01 мм
  нельзя.
- Список операций с размерами (`swXmlContents/KeyWords`) есть во всех
  файлах; по нему видно «добавлена Бобышка-Вытянуть6», «Скругление20: D1
  8 → 12». Погашенность в нём не найдена.
- Состав сборки (`COMPINSTANCETREE`) и модель чертежа
  (`SW-Config-Model-View-Sheet-List`) читаются из файла — это может
  заменить `links.ps1` для нового контейнера.
- «Сохранить как» сохраняет номер корня `KeyWords` (время создания
  файла): у 42 групп по-разному названных файлов номер общий. Это сильная
  подсказка «версии одного исходника», но не доказательство — оговорки в
  [sldprt-design.md](sldprt-design.md) §8.
- Деталь, производная от другой (операция `Stock` в манифесте), — тот
  случай, где беглая форма по сетке расходилась с SolidWorks.

## Состояние на 15.11.2026

- `nonius-sldprt` читает из файла: секции по центральному каталогу
  (`container/`), сетку показа, метки и превью (`glance.rs`, `mesh.rs`),
  замысел — список операций с размерами, манифест, свойства, состав
  сборки, модель чертежа, признаки спорной детали (`design/`).
- В ядре есть точка `DesignSource` и сравнение двух замыслов
  (`nonius_core::design`). Разбор папки и окно ими пока не пользуются:
  связи файлов по-прежнему спрашиваются у SolidWorks (`links.ps1`).
- Не воплощено: точная форма Parasolid и эскизы (их разбирает cadmpeg),
  точные значения размеров из PMI, уравнения, сопряжения, старый
  контейнер OLE.
