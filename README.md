# Nonius

**Контроль версий для CAD-моделей.** Хранит каждую версию деталей и сборок, подсвечивает цветом, что изменилось, и связывает модели с заметками конструктора. Работает с SolidWorks и с любым CAD через STEP. Открытый, бесплатный, делается вместе с людьми и ИИ.

> Нониус — шкала штангенциркуля, которая показывает самые малые различия между двумя положениями. Программа делает то же самое с версиями моделей.

**Статус: ранняя разработка.** Уже работает: проект, импорт STEP/SLDPRT, версии деталей на git + LFS, история, сравнение паспортов версий, сравнение формы с цветной подсветкой, окно с 3D, откат и выгрузка. Аддин SolidWorks и заметки — следующие этапы.

## Зачем

- SolidWorks без серверного PDM не даёт удобной истории версий, а git видит в SLDPRT только «файл изменился».
- Готовые PDM дорогие, закрытые и переносят на механиков ветки программистов.
- Почему сделано именно так — нигде не записывается и теряется.

## Что будет уметь

- **История каждой детали** с превью и описанием изменений; откат к любой версии.
- **Цветная подсветка изменений:** добавленный материал зелёным, убранный красным, сдвинутый жёлтым.
- **Изменения дерева построения:** `D1@Эскиз2: 40 → 45 мм`, «добавлена Фаска1».
- **SolidWorks и любой CAD:** аддин для SolidWorks, остальное через STEP.
- **Совместная работа:** лидер утверждает версии, остальные получают их при синхронизации со ссылкой на скачивание.
- **Заметки как в Obsidian:** `[[кронштейн@v3#Фаска1]]`, обратные ссылки, граф связей.
- **Доступ для ИИ:** MCP, API и командная строка; у агента своя роль и права.
- **Local-first:** проект — обычная папка с открытыми форматами (STEP, YAML, Markdown, git).

## Попробовать

Нужны [Rust](https://rustup.rs) 1.85 или новее, [Git](https://git-scm.com) и [Git LFS](https://git-lfs.com).

```sh
cargo install --path crates/nonius-cli

nonius init мой-станок --name "Станок ЭЭО"
cd мой-станок

nonius import ~/модели/кронштейн.step      # деталь «кронштейн» с model.step
nonius import ~/модели/вал.sldprt          # файл SolidWorks: STEP для сравнения Nonius получит сам
nonius intake ~/модели/станок              # разобрать папку: показать, как Nonius её разложит
nonius intake ~/модели/станок --apply      # ...и разложить: детали, сборки, версии, чертежи
nonius intake ~/модели/станок --deep       # план с проверкой формы всех деталей: найдёт похожие и копии
nonius intake ~/модели/станок --ask        # Nonius спросит о сомнительном по одному вопросу и пересчитает план
nonius status                              # что изменилось
nonius commit кронштейн -m "Первая версия"  # v1
# ...правите модель, импортируете заново...
nonius diff кронштейн                      # чем текущее отличается от последней версии
nonius commit кронштейн -m "Толщина 4 → 5 мм под новый вал"   # v2
nonius log кронштейн                       # история, новые первыми
nonius diff кронштейн v1 v2                # сравнить две версии
nonius restore кронштейн v1 -m "v2 не подошла"   # v3 = содержимое v1, история цела
nonius compare кронштейн --file новая.step       # сравнить, ничего не сохраняя
nonius part rename кронштейн скоба               # версии остаются при детали
nonius part delete скоба                         # остаётся в истории
nonius part recover скоба                        # вернуть удалённую
nonius export кронштейн v2 ./для-лазера    # выгрузить файлы версии
nonius files кронштейн v1 v2               # какие файлы изменились
nonius open кронштейн docs/чертёж.pdf --version v2   # открыть копию файла версии
nonius open кронштейн model.step --programs          # чем система умеет открывать файл
nonius open кронштейн model.step --with Компас       # открыть в этой программе
nonius open кронштейн model.step --folder            # показать файл в папке
nonius file add кронштейн технология.md              # свой файл в docs/ детали
nonius show кронштейн docs/технология.md             # текстовый файл целиком
nonius file remove кронштейн docs/технология.md      # убрать файл, в версиях он есть
nonius hide кронштейн v1                             # убрать старую версию с карты (unhide — вернуть)
nonius folder new "Станина/Узлы"                     # папка-группа, это обычная папка на диске
nonius part move кронштейн "Станина/Узлы"            # перенести деталь, версии остаются при ней
nonius part new вал --in "Станина/Узлы"              # новая деталь сразу в папке
nonius map                                           # дерево проекта (--json — для программ и ИИ)
nonius upgrade                                       # проект старого формата (parts/) → папки
```

**Файлы SolidWorks.** Если на компьютере установлен SolidWorks, при импорте `.sldprt` или `.sldasm` Nonius сам просит его выгрузить STEP и кладёт рядом с деталью — выгружать руками не нужно. SolidWorks при этом можно не открывать: Nonius запустит его невидимо и закроет за собой (первый раз это дольше). Открытый SolidWorks он не закрывает; если деталь открыта с несохранёнными правками — попросит сначала сохранить её. Без SolidWorks файл тоже импортируется, но форму и массу Nonius узнает только из STEP, добавленного отдельно.

**Разбор папки.** Не нужно заводить детали по одной. Покажите Nonius папку, где модели, чертежи и бумаги лежат как попало: он сам поймёт, что `вал.sldprt`, `вал.step` и `вал.pdf` — одна деталь, что `вал_v2` — её следующая версия, какой чертёж к какой модели относится и какие детали входят в какую сборку (последнее — если установлен SolidWorks). Догадку «это версии одной детали» он проверяет формой: похожи габариты и объём — версии, не похожи — разные детали, и в плане написано почему. Если проект копировали папками («рабочая версия», «готовая версия»), одинаковые файлы становятся одной деталью, а изменённые — её версиями. Где он не уверен — спрашивает («Это версии одной детали?») и показывает улики — в том числе что изменилось словами («новое отверстие ⌀8», «убрана бобышка»); ваш ответ сильнее его догадок. Сначала он показывает план и ничего не меняет; исходная папка остаётся как была.

Дерево проекта — это обычные папки: деталь — папка с `meta.yaml`, раскладывать их можно как удобно. Каждая версия — коммит git, который трогает только папку детали; модели хранятся через Git LFS. Историю видно и в обычном `git log`.

### Окно

Двойной щелчок по `nonius.exe` или команда `nonius` без параметров открывает окно: слева детали проекта, сверху выбор версий «Было» и «Стало», в середине деталь в 3D (добавленное зелёным, убранное красным), справа места изменений и числа. Мышь — как в SolidWorks: средняя кнопка вращает, Ctrl + средняя сдвигает, колесо приближает к курсору, Ctrl+1…7 — стандартные виды. Выделять — как в Проводнике: щелчок, Ctrl+щелчок, Shift+щелчок или рамкой мышью с пустого места, в дереве и в «Структуре». Delete удаляет выделенное (несколько — одним вопросом, ход и «Остановить» внизу), Ctrl+A выделяет всё, Esc снимает выделение, F2 переименовывает, Enter открывает. В меню правой кнопки ↑/↓ выбирают пункт, в окошках ←/→ выбирают кнопку, Enter нажимает.

Проекты открываются вкладками, как в браузере, и открываются снова при следующем запуске. Папка для начала работы не нужна: «Новый проект» (и первый запуск) открывает черновик «Без имени», а «Сохранить проект как…» переносит его со всеми версиями в выбранную пустую папку. Закрыть несохранённый черновик с деталями окно даст только после вопроса; «Не сохранять» отправляет его в Корзину, откуда его можно вернуть.

Дерево слева — это папки проекта на диске: папку раскрывают щелчком, деталь перетаскивают мышью на другую папку или на пустое место внизу (в корень), версии остаются при ней. Над центром переключатель «Деталь (3D) / Структура»: в «Структуре» весь проект по папкам карточками, деталь без модели видна как заготовка с кнопкой «Добавить модель…». «Файл → Настройки…»: на вкладке «Проект» — название и допуск сравнения (хранятся в `project.yaml`, едут с проектом), на вкладке «Программа» — как показывать деталь на этом компьютере.

```sh
nonius view кронштейн v1 v2    # сразу открыть деталь и сравнить версии
```

## Устройство

```
crates/
├── nonius-core/   # ядро: формат проекта, схемы файлов, точки расширения, контрактные тесты
├── nonius-store/  # хранилище версий на git + Git LFS
├── nonius-step/   # модуль: чтение заголовка STEP (какая CAD, автор, протокол)
├── nonius-occt/   # модули на OpenCascade: геометрия, сравнение формы, подсветка
├── nonius-solidworks/  # модуль: STEP из .sldprt/.sldasm силами установленного SolidWorks
├── nonius-scene/  # модель 3D-сцены изменений и её файл glTF
├── nonius-gui/    # окно программы: детали, версии, 3D с подсветкой
└── nonius-cli/    # команда `nonius` и запуск окна
docs/
└── ARCHITECTURE.md
```

Ядро маленькое, всё остальное — модули: источник геометрии, источник дерева, сравнение, отрисовка, экспорт, события, интерфейс. Подробно — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
