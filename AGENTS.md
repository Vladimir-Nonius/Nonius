# Правила для участников и ИИ-агентов

Этот файл читают люди и агенты (Claude Code, Codex и другие) перед любой работой в репозитории.

## Что за проект

Nonius — контроль версий для CAD-моделей: SolidWorks и любой CAD через STEP. Архитектура — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Не меняйте архитектуру молча: если задача требует нового трейта, точки расширения или поля в схеме файла — опишите это в pull request отдельным пунктом.

## Главные правила

1. **Маленькое ядро.** `nonius-core` содержит только формат проекта, схемы файлов, имена, точки расширения и реестр. Чтение STEP, подсветка, интерфейс, сервер — отдельные крейты-модули.
2. **Модули подключаются через трейты `nonius_core::extension`** — встроенные так же, как сторонние. Каждый модуль прогоняет в тестах свою проверку из `nonius_core::contract`.
3. **Схема файла меняется только с миграцией.** Новое поле — `#[serde(default)]`. Несовместимое изменение — повысить `Versioned::CURRENT` и написать `migrate` с тестом на старый файл.
4. **Стабильная запись файлов.** Словари — `BTreeMap`, порядок полей фиксирован, чтобы `git diff` был чистым.
5. **Ничего не удаляется.** Код, который стирает версии, историю или чужие файлы, не принимается.
6. **Сообщения для человека — по-русски**, понятным языком механика: что случилось и что делать. Идентификаторы в коде — по-английски, документация к ним — по-русски.
7. **Без `unsafe`** (запрещён в workspace). Исключение — будущий FFI-слой OpenCascade в отдельном крейте.
8. **v1 не переусложнять.** Лишние функции — в issue «на будущее», не в код.

## Перед pull request

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

CI проверяет то же самое на Linux и Windows и минимальную версию Rust 1.82.

## Pull request

- Одна задача — одна ветка — один PR. Ветки агентов: `claude/<задача>`, `codex/<задача>`.
- В описании: что сделано, почему, как проверено, что осталось.
- Тесты обязательны для новой логики. Для модулей — контрактный тест из `nonius_core::contract`.
- В основную ветку PR сливает только лидер проекта.
